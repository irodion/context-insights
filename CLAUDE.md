# Context Insights — working notes for agents

Personal tool: it parses CLI-agent session logs and shows where prompt-cache
breaks cost tokens. Not a product. Keep it small, readable, stdlib-only.
No production dancing — no packaging, no abstraction layers bought on credit.

## Vocabulary

`CONTEXT.md` is the ubiquitous language: Session, Request, Turn, Cache Break,
Expected Cache, Re-billed Tokens, Compaction, Hit Rate. Use those exact terms in
code, CLI output and commit messages. A new concept goes into `CONTEXT.md`
before it appears in code.

## Layout

- `parse_codex.py` — Codex and Claude Code adapters + analysis + CLI. The whole
  tool, for now; the name is a leftover from when there was one Agent Source.
- `test_parse_codex.py` — stdlib `unittest`; synthetic Codex rollouts through the
  real adapter, plus the analysis, Waterfall and Watch Mode tests. Tests sit at
  agreed seams, not on internals.
- `test_claude_adapter.py` — the same, for Claude Code transcripts. One suite per
  Agent Source: each owns the log grammar it speaks, so the next adapter adds a
  file rather than a section.
- `support.py` — the few fixture helpers neither grammar owns. Not named
  `test_*`, so `discover` does not import it as a suite.
- `waterfall.html` — static viewer, opened straight from disk. Served over http
  by `--watch`, it polls the data file and re-renders in place.
- `waterfall_data.js` — generated by `--web`, gitignored. Never hand-edit.
- `CONTEXT.md` — vocabulary.
- `docs/tickets/NNN-*.md` — the backlog; Goal / Scope / Decisions / Acceptance.

## Commands

```sh
python3 parse_codex.py                   # sessions ranked by re-billed tokens
python3 parse_codex.py --source codex    # one Agent Source (default: all of them)
python3 parse_codex.py --all             # include subagent sessions
python3 parse_codex.py --session FILE    # per-request detail for one session file
python3 parse_codex.py --explain FILE    # why each cache break happened
python3 parse_codex.py --web             # regenerate waterfall_data.js
python3 parse_codex.py --watch           # follow the live session, serve the waterfall
```

Tests are stdlib `unittest`, no runner to install:

```sh
python3 -m unittest discover -p 'test_*.py'   # everything
python3 -m unittest test_claude_adapter       # one Agent Source's suite
```

Lint and type-check exactly as the pre-push hook and CI do:

```sh
uv run --no-project --with-requirements requirements-dev.txt ruff check .
uv run --no-project --with-requirements requirements-dev.txt ruff format .
uv run --no-project --with-requirements requirements-dev.txt mypy
```

## Conventions

- Python 3.13+, standard library only. A third-party dependency needs a reason
  written down in the ticket that introduces it.
- New code carries type annotations. `parse_codex.py` now requires them
  (`disallow_untyped_defs`), because an unannotated adapter would satisfy
  `SessionLoader` without conforming to `Session`. The test file is still
  `check_untyped_defs` only, so `def test_...(self)` stays bare.
- Adapters normalize into the `Session` and `Request` TypedDicts, which are the
  seam: an adapter is a `SessionLoader`, and everything past it — analysis, the
  Waterfall, the CLI — sees only those fields and must not know which agent
  produced them. A field only one source records is `NotRequired`.
- Heuristic thresholds live as named constants at the top of the module with a
  comment saying what they mean.
- One ticket per unit of work. Update the ticket's Status/Decisions in the same
  commit as the code. Commit subject: `Ticket NNN: what changed`.
